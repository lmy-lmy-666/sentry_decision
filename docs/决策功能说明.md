# sentry_decision 功能说明

> 场上哨兵在不同情况下会做什么，以及同时遇到多种情况时如何处理

---

## 一、六大状态总览

| 状态 | 什么时候进 | 哨兵做什么 |
|------|-----------|-----------|
| IDLE | 比赛还没开始/结束了 | 原地不动，不发任何导航指令 |
| PATROL | 默认，没有其他事做 | 按 patrol 路线巡逻，后期切保守巡逻 |
| DEFEND | 发现敌人/被打了/空中威胁 | 进入战斗流程，跟踪、交战、闪避 |
| ATTACK_PUSH | 前压条件全满足 | 向敌方半场推进 |
| RESUPPLY | 弹药没了或血量偏低 | 开车去补给区 |
| RETREAT | 血量危急（<60） | 撤到安全点保命 |

---

## 二、每个状态详细说明

### IDLE

```text
触发：裁判数据失效 / 比赛未运行 / 比赛结束
行为：不发任何导航目标，取消已有导航
退出：比赛开始且裁判数据正常
```

### PATROL

```text
触发：默认状态，无更高优先级任务
行为：按 patrol 路线循环巡逻，每个点驻留 dwell_s 秒
     比赛后期（<60s）自动切 fallback_patrol
     导航卡住自动跳下一个点
退出：被任何高优先级状态抢占
```

### DEFEND

```text
触发：敌人在附近 / 正在被攻击 / 空中威胁
行为：
  SCOUT     → 搜索敌人，沿 defend_fallback 路线防守巡逻
  TRACK     → 跟踪敌人，距离>3m跟踪（每1s更新追击目标），<3m进入交火（10s超时回 SCOUT，防止被钓鱼）
  ENGAGE    → 交战，停住射击。敌人退到4.5m外自动回TRACK缩近距离（30s超时回 SCOUT / 敌人>8m跑远直接回 SCOUT）
  EVADE     → 被击中时不跑，自瞄持续反击，1s没再被打→回SCOUT还手
  HARDEN    → 空中威胁时进入强化防御，持续15s
  EVADE_AIR → 强化防御后用完，转为不规则移动防空
退出：威胁消失超过 5s → 回 PATROL 或 ATTACK_PUSH
```

### ATTACK_PUSH

```text
触发：前哨站存活 + 血量>=180 + 弹药充足 + 不过热 + 没被打 + 非保守后期
行为：按 attack_push 路线前压，导航卡住跳下一个点
     有双倍易伤窗口时切强化进攻姿态
退出：条件不满足 / 被攻击 → 退出
```

### RESUPPLY

```text
触发：弹药 <= 0 → 不管有没有敌人都去补给（没弹药没法打）
     血量 < 150 且弹药充足 → 仅无敌人才去补给
行为：开车去 supply 点，到补给区后 RFID 确认
     60s超时 → 尝试 backup_supply_points
     备用也用完 → 放行退出（血量危急保持，否则回 PATROL）
保持：没弹药时即使有敌人也不退出补给
     有弹药时敌人出现→让路给 DEFEND
退出：弹药补足且血量恢复到满（地图大不好走，到一次就补满）/ 补给失败兜底
```

### RETREAT

```text
触发：血量 < 60
行为：优先撤到 retreat 点（安全优先）
     血量<5%切强化防御保命
     导航卡住/timeout → backup_retreat_points → supply（回血补弹）→ safe_cover 多级兜底
退出：血量恢复到 > 120
```

## 三、多状态叠加时的处理顺序

哨兵可能同时满足多个状态的条件，FSM 按以下优先级依次判断：

```text
1. IDLE         ← 裁判掉线/比赛结束 → 什么都不做，最高优先
2. RETREAT      ← 血量<60 → 保命第一，任何情况都先撤
3. DEFEND(空中) ← 雷达/自瞄检测到空中威胁 → 先防空
4. RESUPPLY     ← 弹药空或血量低，且敌人不在 → 趁安全去补给
5. DEFEND(地面) ← 敌人在附近/被攻击 → 应战
6. ATTACK_PUSH  ← 条件允许 → 前压进攻
7. PATROL       ← 都没事 → 巡逻
```

## 四、常见叠加场景举例

### 场景 1：正在前压，突然被敌人打

```text
当前状态：ATTACK_PUSH
情况：血量 300，收到被攻击信号
处理：attack_push_allowed 检查到 under_attack → 不允许前压
     权重链掉到 DEFEND(地面) → 进入战斗
结果：哨兵停止前压，开始应战
```

### 场景 2：正在应战，血量掉到 140

```text
当前状态：DEFEND/ENGAGE
情况：血量 140，弹药充足，敌人还在
处理：血量 140 < 150 → needs_resupply()=true
     但敌人还在 → 不进 RESUPPLY（防止来回切）
     权重链继续 DEFEND → 保持应战
结果：继续战斗，不会边打边往补给区跑
```

### 场景 3：正在应战，血量掉到 50

```text
当前状态：DEFEND/ENGAGE
情况：血量 50，敌人还在
处理：RETREAT 优先级(2) > DEFEND(5) → 直接抢断
     进 RETREAT，切防御姿态，撤到安全点
结果：不管战斗多激烈，先跑
```

### 场景 4：正在撤退，敌人出现

```text
当前状态：RETREAT
情况：血量 80，敌人在 5m
处理：血量 80 < 120(retreat 退出阈值) → 保持 RETREAT
     不会因为敌人出现而切 DEFEND
结果：继续撤退，不与敌人纠缠
```

### 场景 5：血量恢复到 130，敌人还在

```text
当前状态：RETREAT
情况：血量 130，敌人在 5m
处理：血量 130 > 120 → 不强制保持 RETREAT
     权重链判断：敌人 detected → DEFEND
结果：退出 RETREAT，开始应战
```

### 场景 6：正在补给，敌人出现

```text
当前状态：RESUPPLY
情况：血量 140，开车去补给区，路上出现敌人
处理：RESUPPLY 保持条件检查到 enemy_detected → 不强制保持
     权重链掉到 DEFEND → 应战
结果：放弃补给，先应战。敌人消失后重新进 RESUPPLY
```

### 场景 7：血量 140，没敌人，弹药空

```text
当前状态：RESUPPLY
情况：血量 140，弹药 0，没敌人
处理：ammo_empty → RESUPPLY → 去补给
     所有补给点超时后 supply_backup_exhausted=true
     血量 140 > 120(保命阈值) → 不再强制保持 RESUPPLY
结果：补给失败后回 PATROL，不会卡死
```

### 场景 8：前哨站存活，血量 400，后期 50s

```text
当前状态：PATROL
情况：前哨站活，血量 400，弹药 50，没有敌人
处理：ATTACK_PUSH 允许条件中 late_game + disable_attack_push → 不前压
     继续 PATROL，且自动切换 fallback_patrol 保守路线
结果：后期不冒进，保守巡逻保分
```

### 场景 9：空中威胁 + 正在被地面敌人打

```text
当前状态：DEFEND
情况：空中威胁标记出现，同时被地面敌人攻击
处理：权重链空中威胁(3) > 地面应战(5) → DEFEND(空中)优先
     切 HARDEN 强化防御，持续 15s
     地面敌人不管——先扛空中
结果：优先防空，强化防御扛住，15s 后切 EVADE_AIR
```

### 场景 10：自瞄断连 / 雷达断连

```text
当前状态：DEFEND
情况：自瞄突然不发数据了
处理：EnemyInfo 0.5s 过期 → enemy_detected()变 false
     权重链中 DEFEND 条件消失 → 降到 ATTACK_PUSH 或 PATROL
结果：不会困在 DEFEND 状态
```

## 五、自我保护机制

| 机制 | 效果 |
|------|------|
| 血量滞后 | 进 RETREAT 用 60，退出用 120；进 RESUPPLY 用 150，补满(400)才退出。防止边界抖动 |
| 最小状态停留 | 普通状态至少 4 tick，防止状态来回切 |
| 姿态冷却 | 姿态切换间隔 >= 5s，DEFENSIVE 和强化防御可绕过冷却 |
| 敌人数据过期 | 自瞄/雷达 1.0s 无新数据自动清除，防止虚假敌人 |
| 补给失败兜底 | 所有补给点超时后 15s 冷却（弹药空绕过），防止 PATROL↔RESUPPLY 死循环 |
| 撤退失败兜底 | retreat → backup_retreat_points → supply → safe_cover 多级兜底，不困在原地 |
| 战斗子状态滞回 | SCOUT↔TRACK 0.2s，ENGAGE→TRACK 1.5×距离+2s 停留，防止子状态闪烁 |
| 战斗超时 | TRACK 10s、ENGAGE 30s 自动退回 SCOUT，防止无限追逐 |
| Fallback 到达 | Nav2 宕机时用 odom 自行判断到达，路线不卡死 |
| **受击持久化** | `under_attack()` 维持 0.5s 滞后窗口：裁判可能在上报后清除 `is_hp_deduced` 标志，持久化窗口防止 tick 错开漏检导致不进入 DEFEND/EVADE |
| **RFID 防抖** | 连续 3 tick (0.3s) 检测到补给区 RFID 才确认到达，防止边缘信号抖动反复重置补给失败标记 |
| **双源 OR 融合** | 自瞄 + 雷达独立维护检测标记和时间戳，读时 OR 融合。自瞄丢锁不丢雷达坐标，雷达断连不丢自瞄检测 |
| **雷达测距同步** | 雷达回调同步更新 `nearest_distance`，纯雷达 TRACK→ENGAGE 距离判定路径畅通 |
| **子状态 goal 统一重置** | 作战子状态切换时 `goal_sent_` 在 `run_combat_fsm` 统一重置，消除 EVADE_AIR→SCOUT 等路径 30s 发呆 bug |
| **后期策略自适应** | 比赛 <60s 时根据盟友基地 HP 自动选择 leading(保守) / trailing(激进) 策略和巡逻路线 |
| **Nav2 竞态保护** | result_callback/feedback_callback 用 goal_id 比对过滤 stale 消息；cancel_nav 始终取消所有 goal |
