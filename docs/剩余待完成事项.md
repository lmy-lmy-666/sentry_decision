## 一、电控（STM32 固件）

### 1. 0xB6 → 0x0120 下行

ROS 端已通过：`sentry_decision` → `sentry/command` → `serial_driver` → `0xB6`

STM32 侧需要新增：

```
收到 0xB6 包 → 解包 → 拼成 0x0120 sentry_cmd → 发给裁判系统
```

0xB6 包结构（15 字节）：

| 字段 | 说明 |
|------|------|
| confirm_revive | bit0：确认复活 |
| confirm_instant_revive | bit1：确认兑换立即复活 |
| projectile_exchange_amount | bit2-12：兑换发弹量 |
| remote_projectile_exchange_count | bit13-16：远程兑换发弹量次数 |
| remote_hp_exchange_count | bit17-20：远程兑换血量次数 |
| stance_command | bit21-23：姿态 1进攻/2防御/3移动/4强化进攻/5强化防御/6强化移动 |
| activate_energy_mechanism | bit24：激活能量机关 |

当前仅 `stance_command` 被决策填充，其余字段预留。

### 2. 0x020D → ROS 上行

裁判系统会下发 0x020D（哨兵自主决策信息同步），包含：

- 是否脱战
- 当前姿态
- 姿态是否强化
- 各姿态剩余时间
- 能量机关是否可激活

STM32 需要新增自定义上行包（如 0xA4），把这些字段转发给 ROS 端 `serial_driver`。

建议消息结构（参考 `rm_interfaces/msg/SentryInfo.msg`）：

```text
bool disengaged
uint8 current_stance
bool stance_enhanced
float32 offensive_remaining_s
float32 defensive_remaining_s
float32 mobility_remaining_s
float32 enhanced_offensive_remaining_s
float32 enhanced_defensive_remaining_s
float32 enhanced_mobility_remaining_s
bool energy_mechanism_activatable
```

### 3. 0x020C → ROS 上行（可选）

裁判系统 0x020C（雷达标记进度）包含：

- 对方机器人易伤标记
- 空中机器人标记
- 双倍易伤窗口

有则更好（可触发空中防御和强化进攻），暂无也不影响基础功能。
