### 状态转移的防振荡规则 (can_leave_current_state)

```
当前状态 → 目标状态:
  IDLE → 任意: 总是允许
  任意 → IDLE / RETREAT / DEFEND: 总是允许 (安全优先)
  RESUPPLY 抢断 (任意 → RESUPPLY): 允许 (除RETREAT外)
  其他转移: 需 ticks_in_state ≥ min_ticks(4 ticks = 400ms)
```

### 各顶层状态详细说明

| 状态 | 进入条件 | 退出条件 | 姿态 | 导航目标 | 卡住/超时处理 |
|------|---------|---------|------|---------|--------------|
| IDLE | 裁判断连(3s) 或 比赛未运行 | 裁判恢复 + 比赛运行 | 无 | 停止 | cancel_nav() |
| RETREAT | hp < 60 (从其他状态) | hp ≥ 120 (hysteresis) | DEFENSIVE | retreat坐标 | 备选撤退→supply→safe_cover 多级兜底 |
| DEFEND(空中) | under_aerial_attack() | 空中威胁消失 | ENHANCED_DEFENSIVE | safe_cover | — |
| RESUPPLY | hp < 150 或 弹药 ≤ 1 (带15s冷却) | hp = 400 或 补给耗尽+hp≥120 | MOBILITY | supply坐标 | 备用补给点 → 冷却重试 |
| DEFEND(地面) | enemy_detected() 或 under_attack() | 无敌方 + 未被攻击 | DEFENSIVE/OFFENSIVE | defend_fallback | 跳点 |
| ATTACK_PUSH | 8条件全满足 | 任一条件失败 | OFFENSIVE | attack_push路线 | 跳点 |
| PATROL | 默认 | — | MOBILITY | patrol路线(后期切fallback) | 跳点 |

## 六、导航路线管理

```
drive_route(route, now_s):
  ┌─ route.empty() → return (不发goal, 不动机器人)
  ├─ path_idx >= size → 重置为0 (循环)
  ├─ !goal_sent_ → publish_goal(wp) → goal_sent_=true, goal_arrived_=false
  ├─ goal_sent_ && !goal_arrived_ → 等(ctx.goal_reached())
  └─ goal_arrived_ && now - arrived ≥ wp.dwell_s → path_idx++ → goal_sent_=false (推进)

publish_single_goal(wp):
  └─ !goal_sent_ → publish_goal(wp) → goal_sent_=true (单次发送,不循环)

各状态使用的路线:
  PATROL:       patrol(后期→ally_base_hp>0?leading:trailing.fallback_patrol)
  ATTACK_PUSH:  attack_push(后期→ally_base_hp>0?leading:trailing 策略)
  DEFEND/SCOUT: defend_fallback
  DEFEND/TRACK: 雷达坐标动态计算目标点(无odom→defend_fallback)
  DEFEND/HARDEN/EVADE_AIR: safe_cover(publish_single_goal)
  RESUPPLY:     supply + backup_supply_points(publish_single_goal, RFID防抖3tick确认)
  RETREAT:      retreat + backup_retreat_points + supply + safe_cover(publish_single_goal)
```

## 七、故障容错矩阵

| 故障场景 | 检测机制 | 响应行为 | 恢复 |
|---------|---------|---------|------|
| 裁判断连 | game_status_fresh() > 3s | → IDLE, cancel_nav | 数据恢复→下一tick退出IDLE |
| 敌人数据断 | enemy_info_fresh() > 1s | enemy_detected()→false, 退出DEFEND | 数据恢复→重新检测 |
| 裁判受击标志瞬时 | under_attack() 0.5s持久化窗口 | 窗口内维持应战/闪避 | 窗口过期→恢复正常 |
| RFID边缘抖动 | 连续3tick确认才判定到达 | 抖动时暂停导航防overshoot | 信号稳定→确认到达 |
| Nav2宕机 | action_server_is_ready()==false | fallback到PoseStamped+odom到达检测 | Nav2恢复→自动切回action |
| Nav2拒绝goal | goal_handle==nullptr | → nav_status=FAILED → nav_stuck → 跳点重发 | 重发成功 |
| Nav2执行失败 | result=ABORTED | → nav_status=FAILED → 跳点 | 下一tick重发 |
| Nav2 stale回调 | goal_id与current_handle不一致 | 回调直接return,不覆盖状态 | 新goal正常处理 |
| 导航卡住 | Nav2反馈 STUCK 状态 | 跳点重发 / timeout兜底 | 重发成功 |
| 补给点不可达 | nav_stuck / 超时60s | → 备用点 → 耗尽→15s冷却→重试 | 冷却到期 or RFID触发 |
| 撤退点不可达 | nav_stuck / 超时90s | → 备用点 → supply → safe_cover | 到达任意点 |
| 路点全部不可达 | 超时跳点循环 | 机器人持续尝试 | 需外部干预 |
| 作战状态无进展 | TRACK 10s / ENGAGE 30s | → 退回 SCOUT | 重新搜索 |
| 子状态goal残留 | run_combat_fsm统一重置 | 切换后立即发新goal | 正常恢复 |
| 空路线 | route.empty() | PATROL标记goal_sent_=true防空转 | 外界切换状态恢复 |
